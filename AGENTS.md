# Permanent project instructions

- Never commit credentials, cookies, tokens, passwords, phone numbers, emails, or other private values.
- Never commit `.env`.
- Never run Drupal write tests on production.
- Never run destructive Drupal operations unless explicitly requested.
- Never delete existing Drupal content.
- Only modify exact `QA-AUTOMATED-`-owned nodes whose identity has been proven.
- Never choose arbitrary Drupal media, taxonomy terms, or references.
- Never run tests against production unless the user explicitly authorizes that specific run.
- All content created by this automation framework must use the `QA-AUTOMATED-` prefix.
- Prefer reusable Drupal field handlers rather than hardcoding complete flows for individual content types.
- Keep tests deterministic and provide useful failure diagnostics.
- Do not silently weaken assertions just to make tests pass.
- Never blindly rerun creation after a save may have succeeded; recover the exact owned node instead.
- Sanitize diagnostic URLs by removing query strings and fragments.
- Never publish Drupal content without explicit `DRUPAL_ALLOW_PUBLISH=true`.
- Publishing remains prohibited on production regardless of opt-in.
- Never publish arbitrary existing nodes.
- Only publish exact `QA-AUTOMATED-` nodes from a known regression run.
- Never weaken moderation or ownership checks to make publishing pass.
- Never bypass Drupal workflow permissions.
- Never introduce a more privileged account without explicit authorization.
- Treat unavailable transitions according to configured role expectations.
- Do not convert blocked workflow states into false passing publication results.
- Never assume Published must immediately follow In review; discover exact available workflow transitions.
- Never bypass required workflow assignment fields.
- Never hardcode personal Drupal user IDs or usernames.
- Never select an arbitrary or ambiguous autocomplete user.
- Never classify an unavailable Published option as a permission failure until the node reaches the state where Published is expected.
- Never assume autocomplete search text equals the resolved Drupal entity label.
- Always verify the exact expected resolved workflow-assignee identity.
- Never log workflow-assignee labels or IDs from local environment configuration.
- Require the configured digits-only workflow-assignee entity ID to match Drupal's post-selection value exactly.
- Never modify arbitrary existing content; normal Paragraph tests create their own uniquely titled `QA-AUTOMATED-` Draft host.
- Existing regression nodes are historical evidence and are never reusable mutation targets.
- Reuse exactly one fieldless default Paragraph when expected; never duplicate it.
- Rediscover saved Paragraph rows, current deltas, and controls after Drupal AJAX rerenders.
- Never retain stale locators across saved Paragraph expansions.
- Keyboard fallback requires one exact, visible, enabled semantic Paragraph `input`/`button` submit control and verified focus ownership.
- Never force-click a Paragraph AJAX Edit control or bypass it through DOM click, synthetic events, direct Drupal AJAX, or JavaScript form submission.
- Never automatically rerun a Paragraph or other write suite after failure.
- Never treat Media Library insertion fields such as `media_library_selection` as persisted association proof.
- After media AJAX, rediscover the exact Paragraph row and delta and reacquire all Paragraph-local controls.
- Resolve automation media by exact owned identity; never select the first or an arbitrary media item.
- Do not automate a required select or color field without a valid safe default or an approved semantic rule.
- Match Paragraph labels containing punctuation with exact escaped boundaries rather than word-boundary shortcuts.
- Paragraph Edit/Collapse controls may render as exact named `input` or `button` elements; require unique ownership either way.
- Leave optional editorial fields untouched unless the authorized scenario explicitly covers them.
- Never choose a required non-default select value merely to make a Paragraph saveable; require a valid default or an approved semantic rule.
- Resolve Blockquote media through the exact automation-owned fixture filename before accepting an environment-specific media ID.
- Prove persisted Paragraph media through the stable `[selection][0][target_id]` association, never the transient `media_library_selection` insertion field.
- After any Paragraph media AJAX operation, rediscover the exact row, runtime delta, and owned controls before continuing.
- Write suites must create their own uniquely titled `QA-AUTOMATED-` host and must never mutate historical regression nodes.
- Never force-click, synthesize DOM events, invoke Drupal AJAX directly, or bypass semantic saved-Paragraph activation.
- Never automatically rerun a write suite after a failure.
- Permit Drupal writes only when `DRUPAL_ENVIRONMENT=develop` and the configured root origin is exactly `https://devv.leidos.com` over HTTPS.
- Reject production, alternate hosts, lookalike subdomains, ports, credentials-in-URL, path-prefixed targets, query strings, and fragments before browser write execution.
